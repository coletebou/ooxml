## 修复如何共享 {#how-the-fixes-are-shared}

所有视觉层面的改动都是同一个更改，同时作用于全部五个绑定，因为每个绑定已经输出相同的 `data-ribbon-group`、`data-ribbon-control` 和 `data-pptx-chrome` 钩子：

- `src/ui/src/pptx/render/editor-chrome/`（`controls-css`、`home-layout-css`、`font-picker-css`、`cluster-css`、`ribbon-collapse-css`）：扁平的 Office 按钮、小行（22-24px）和大磁贴（66px）、通过 `order` 加零高度换行实现的两行“字体”和“段落”、堆叠的“编辑”和“绘图”列、以内嵌细线和 11px 标题撑开功能区的组外壳。功能区内容行为 92px（原为 82px）。
- `ribbon-group`（共享元素）：细线分隔符、11px 标题、可选的启动器、折叠后的外观。`ribbon-command`：标题上方 32px 的图标、`dropdown` 下拉箭头、`tall` 仅图标磁贴（绘图）。
- “开始”系列（`ribbon-home-families.ts`）：`large` 和 `stack` 标志以及可见标题。
- “插入”视图：大命令，“形状”和“图表”为库菜单，SmartArt 位于“图表”之前。
- `attachRibbonOverflow(content, { launchers })`（`ribbon-overflow.ts`、`ribbon-launchers.ts`）：见下文。

绑定层面的改动很小：一个“字体”组（字体系列和字号并入“字体”组）、标题和行钩子、“绘图”在“编辑”之前、溢出挂接（React ref 回调、Vue 函数 ref、Angular `[pptxRibbonOverflow]`、Svelte `use:ribbonOverflow`、Vanilla 按窗格），以及“设计”命令不再是 `compact`。

### 窄窗口 {#narrow-windows}

当宽度低于某个选项卡所需宽度时，各组从右到左折叠为一个按钮（图标、标题、下拉箭头），其命令在弹出窗口中打开（Escape、点击外部和普通命令会将其关闭；带有自身菜单的控件会保持其打开）。只有 `home.*`、`insert.*`、`draw.*` 和 `design.*` 组会折叠（`ribbon-overflow.ts` 中的 `COLLAPSING_GROUPS`）；其他选项卡仍然滚动。移动布局（768px 以下）保持不变。

### 对话框启动器 {#dialog-launchers}

“字体”“段落”和“绘图”显示右下角的启动器图标。查看器没有模态的“字体”或“段落”对话框，因此它们各自打开“属性”窗格，并在工具提示中说明这一点。“剪贴板”没有对应的窗格。

## 下一轮的注意事项 {#gotchas-for-the-next-pass}

- 共享的 `ribbon-command` 不得有与其特性同名的实例字段（`label`）：当该属性存在时，React 19 会赋值 `element.label = ...`，并悄然破坏该元素。
- 查看器的基线 `button { min-height: 24px }` 在 Svelte 中优先级高于 22px 的行；“开始”规则在内容钩子上重复 `[data-pptx-chrome]` 以取胜。
- React 和 Angular 从其构建后的 `dist` 读取共享 UI：请重新构建（`bun run --cwd src/ui build`、`bun run --filter pptx-angular-viewer build`），并在清除 `demos/pptx/demo-angular/node_modules/.vite` 之后重启 Angular 演示。
- 折叠按组 ID 前缀选择启用；当其他选项卡进行改进时，请扩展 `COLLAPSING_GROUPS`，并为“切换”更新 `ribbon-compact-layout`。
