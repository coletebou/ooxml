# 与 PowerPoint 的功能区对等：切换、动画、幻灯片放映、录制、审阅、视图和上下文选项卡 {#ribbon-parity-with-powerpoint-transitions-animations-slide-show-record-review-view-and-contextual-tabs}

本页记录了功能区与 Microsoft PowerPoint（Microsoft 365，当前外观）的对比审核，以及所做的更改。它涵盖“切换”“动画”“幻灯片放映”“录制”“审阅”和“视图”选项卡，以及上下文选项卡（图片格式、形状格式、表设计、图表设计、SmartArt 设计）。“开始”“插入”“绘图”和“设计”由另一项更改涵盖。

::: warning 某一时间点的审核
这是 2026 年 10 月的审核，“未修复”条目是其发现，而不是实时状态。此后新增了“表布局”选项卡和“图表格式”选项卡（功能区目前注册的上下文选项卡为 `shapeFormat`、`pictureFormat`、`tableDesign`、`tableLayout`、`chartDesign`、`chartFormat` 和 `smartArtDesign`，请参阅 `src/ui/src/pptx/render/toolbar-actions.ts` 中的 `RIBBON_CONTEXTUAL_TABS`）。SmartArt 格式和视频/音频格式选项卡仍不存在。在据此行动之前，请对照代码重新核实相应条目。
:::

## 方法 {#method}

- 参照：通过 COM 和 UI 自动化驱动 PowerPoint，在一份临时演示文稿（一张幻灯片，包含一个形状、一个表格、一个图表、一个 SmartArt 图形和一张图片）上操作。每个选项卡都在 1400 px 逻辑宽度下从真实窗口截取。未保存任何内容，之后已关闭 PowerPoint。
- 查看器：每个绑定都在 e2e 测试套件所用的示例演示文稿上以 1400 x 800 截取。截图位于 `docs/public/assets/ribbon-parity/<tab>/`，文件名为 `powerpoint.png`、`viewer-before-<binding>.png` 和 `viewer-after-<binding>.png`。五个绑定都通过共享元素渲染这些选项卡，因此一次修复会同时落到 React、Vue、Angular、Svelte 和 Vanilla；为每个绑定保留截图正是为了证明这一点。
- 查看器保留其深色主题和紧凑密度（请参阅 `DESIGN.md`）；比较针对的是结构、分组、按钮大小、图标位置和可操作提示，而不是配色。

严重程度：**高**会改变选项卡的使用方式或用户期望找到的内容，**中**是明显的视觉或结构不一致，**低**是细节打磨。

## 跨领域更改 {#cross-cutting-changes}

- `pptx-ui-ribbon-command` 接受 `caret` 特性，并在最后一行标签之后绘制下拉箭头；一个共享集合（`RIBBON_MENU_COMMAND_IDS`）为“幻灯片放映”“录制”和“审阅”的菜单命令启用它，无需逐绑定接线。
- 当 `pptx-ui-ribbon-group` 的子项全部为小型下拉库或命令时，它会将自身标记为 `data-stack`，并以每列三个的方式排布。
- `pptx-ui-ribbon-gallery` 可以绘制单按钮命令（`descriptor.command`）：无面板，大或小，并带有说明其为何禁用的工具提示。SmartArt 的创建图形和重置使用它，因此没有绑定需要新组件。
- 现在“录制”在每个绑定中默认使用大按钮。

## 未涵盖（需要产品决策）{#not-covered-needs-a-product-decision}

悬停、按下和禁用状态、工具提示、焦点环以及窄宽度折叠都已比较，其行为已与 PowerPoint 一致（扁平悬停填充、带强调色的按下状态、变暗的禁用状态、原生 `title` 工具提示、2 px 焦点环）。折叠为溢出是查看器自有的移动端面板，不在本次范围内。

## 测试 {#tests}

- `e2e/pptx/ribbon-parity-other-tabs.spec.ts`（在每个绑定项目上运行）断言组名称和顺序、大命令与小命令、磁贴结构、“视图”的“显示”网格，以及每个上下文选项卡针对其对象类型的外观和分组。
- 单元测试：`ribbon-animations.test.ts`、`ribbon-transitions.test.ts` 和控件名称测试已针对新的结构和字符串更新。

## 按优先级排列的后续步骤（上文所有标记为“未修复”的内容）{#prioritised-next-steps-everything-marked-not-fixed-above}

1. 上下文命令组（高）：形状格式和图片格式上的插入形状、排列（上移一层、下移一层、选择窗格、对齐、组合、旋转）、大小（高度、宽度、裁剪）和替换文字。复用 `pptx-ui-ribbon-gallery` 现在支持的单按钮命令条目（`descriptor.command`）或“开始”的排列条；每个绑定的工作是将现有的叠放次序和大小操作接入库上下文。
2. SmartArt 格式和视频/音频格式选项卡（高；图表格式此后已添加）：一旦其命令存在（图表元素格式；逐节点 SmartArt 格式），就将它们加入 `RIBBON_CONTEXTUAL_TABS` 和 `CONTEXTUAL_TAB_GROUPS`。“表布局”已完成；其剩余差距为选择、查看网格线、单元格边距、数值型单元格大小和表格大小字段，以及排列组。
3. SmartArt 节点（中）：功能区级别的选中节点概念将启用升级、降级、上移、下移和文本窗格，它们目前被禁用并带工具提示。转换和从右到左需要引擎支持。
4. 切换和动画的广度（中）：待播放支持后增加更多切换缩略图、功能区级别的延迟和重新排序动画按钮（动画窗格两者皆有）、悬停预览。
5. 幻灯片放映和录制（中）：待查看器有相应模型后，增加监视器组、屏幕录制、音频、导出、预览。
6. 视图（中）：颜色/灰度需要灰度渲染模式。
7. 低优先级打磨：库条磁贴数量（`INLINE_GALLERY_TILE_COUNT`）、上下文选项卡标题上的强调色、将“幻灯片放映”的选项合并到“设置”组中。

## 下一次会话的注意事项 {#gotchas-for-the-next-session}

- 修改共享 UI 后，需要在仓库根目录的 `src/ui` 中运行 `bun run build`，然后在运行 Playwright 之前运行 `bun run --filter pptx-angular-viewer build`（以及语言文件），否则 dist 新鲜度守卫会中止运行。（`packages/angular` 中的 `inline-shared` 现在只会标记版本文件。）
- 在“动画”库中查找文本药丸或标题的绑定单元测试，现在使用 `button.preset` 和列的 `aria-label`。
- vanilla 的 `PptxViewer.test.ts` 在高负载下可能因内存不足使工作进程崩溃；请单独使用 `NODE_OPTIONS=--max-old-space-size=6144` 重新运行。
